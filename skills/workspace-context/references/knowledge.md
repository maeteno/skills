# KNOWLEDGE 规则

`KNOWLEDGE` 是人工沉淀的通用知识（技术规范、领域概念、方法论、跨项目经验），不绑定项目或仓库，也不是 AI 维护的 wiki，两者互不替代。

1. 所有 KNOWLEDGE 集中在根目录 `knowledge/` 下。工作区级知识的实体目录是 `knowledge/workspaces/<工作区目录名>/`，只服务同名工作区；`knowledge/` 下的其他内容是根目录级知识。两者都不进 `index.yaml`。
2. 默认不纳入搜索。不自动扫描、索引、迁移、同步或改写其中内容。用户明确指定路径和范围后才可读取；仅在明确要求编辑指定内容时写入。该授权不解除根目录边界和工作区隔离。
3. 工作区内的入口是软链接 `knowledge -> ../knowledge/workspaces/<工作区目录名>`，是根目录内的受控例外，只能指向本工作区对应的实体目录。不得通过它或 `knowledge/workspaces/` 访问其他工作区的知识；根目录级知识不链接到工作区。
4. 工作区内的 KNOWLEDGE 应在该工作区 `AGENTS.md` 中以相对路径登记。工作区搜索按登记路径排除，不靠递归扫描发现。已知存在但未登记或归属不明时，先问用户，不读写。

## 创建工作区级 KNOWLEDGE

创建与登记属于初始化任务，通常由 `work-dir` 技能完成。手工处理时：

1. 先在 `knowledge/workspaces/` 下建立与工作区同名的实体目录。
2. 再在工作区根目录创建相对软链接。
3. 在工作区 `AGENTS.md` 中登记 `knowledge/`。
4. 工作区内已有同名真实目录时，仅在为空时替换为软链接；非空则先问用户，不自动迁移或合并。
